# 通用网站单账号登录会话计划

日期：2026-08-23

## 目标

让操作者为一个公开网站打开可见浏览器并人工完成登录，保存该网站的登录会话；以后采集同一精确域名的详情页时，系统自动复用该会话。

## 已确认范围

- 政府官网、Bing News RSS、社交平台继续作为三个独立来源组，没有先后依赖。
- 每个精确域名只保留一个账号；再次保存直接覆盖旧会话。
- 只保存浏览器会话，不保存或自动填写用户名、密码。
- 验证码和登录步骤由操作者在可见浏览器中完成。
- 登录会话仅用于与保存时相同的 HTTPS 主机名，不通配子域名，也不跨域复用。
- 详情页抓取顺序为：匹配的已保存会话、Scrapling、现有普通请求。

## 本轮不做

- 多账号、账号列表、账号切换、会话导入导出。
- 自动输入密码、自动处理验证码、自动判断任意网站是否已经登录。
- 为每个网站定制搜索规则；URL 仍由现有政府来源、Bing News RSS 或社交来源发现。
- 把通用网站登录混入现有社交平台账号结构。

## 实现切片

1. 为通用网站增加严格 URL 校验、每域名单会话、过滤后的会话保存和临时浏览器上下文。
2. 在现有浏览器登录 API 上增加 `site_url` 分支，保持原有 `platform` 分支兼容；状态接口不返回任何会话明文。
3. 让详情页采集按目标 URL 自动查找同域名会话，并在受限浏览器中读取页面；失败后回退现有抓取链。
4. Web 页增加一个 URL 输入卡和打开、保存、关闭、清除操作，不增加账号切换界面。
5. 运行单元、接口、采集回归和本地页面真实浏览器验证，再做安全与代码审查。

## 验收标准

- 同一域名第二次保存后只剩一个会话记录，且使用最新内容。
- 不同域名相互隔离，清除一个域名不会影响其他域名或社交平台。
- 非 HTTPS、带账号凭据、本机/私网/保留地址和无法安全解析的 URL 被拒绝。
- 保存的数据只含目标主机可用 Cookie 和目标同源存储，并使用现有 Windows DPAPI 加密。
- 自动读取前、主页面跳转时和读取完成后都校验精确主机名；不会把会话交给 Scrapling 或普通 HTTP 请求。
- 匹配会话成功时能补充详情正文；会话失效或读取失败时保留原结果并回退，不把失败误报为成功。
- 原有社交平台登录、Bing News RSS 和政府来源测试不回归。

## 已知限制

- 当前会在浏览器请求前检查公网 DNS，并限制 HTTP/WSS 协议、端口和精确域名；但 DNS 校验后 Chromium 会再次解析域名，若需要对 DNS 重绑定形成强隔离，仍需固定解析或受限出站代理/防火墙。
- 本轮真实浏览器验收覆盖本地界面渲染、四个操作请求和控制台状态；真实第三方账号登录与正文效果仍需使用甲方提供的测试站点和账号做现场验收。

## 风险和处置

| 风险 | 影响 | 处置 |
|---|---|---|
| 当前 `.venv` 继承共享包 | 无法证明依赖可复现 | D1 在可丢弃目录建立完全隔离环境 |
| 多个 Python 子运行时和动态桥接 | PyInstaller 冻结后易破坏路径和运行方式 | 首版使用安装器创建私有运行时 |
| Playwright/Scrapling 下载失败 | 安装不完整 | 固定版本、下载源、校验、重试和修复流程 |
| API Key 被本机子进程继承 | 无法宣称子进程不可见 Key | 固定并审计子运行时；如不可接受则暂停并重新定范围 |
| B站传递依赖为 GPL-3.0-or-later | 正式分发可能产生源码和许可证义务 | D4 完成许可证/分发审查；未完成前不外发该子运行时 |
| 数据与程序位于同一根目录 | 升级/卸载可能误删用户数据 | 安装器显式保留 `data/`、`output/`，删除需单独确认 |
| 第三方网站与账号状态变化 | 自动测试无法证明现场可用 | 使用甲方账号和冻结样例做独立现场验收 |
| 本机目录误入候选 | 泄露账号、会话、历史或材料 | 严格白名单、dry-run、敏感扫描和用户先审阅 |
